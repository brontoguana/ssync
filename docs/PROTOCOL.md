# SSync 4 authenticated channel

Selected libraries: opaque-ke 4.0.1 and snow 0.10, locked in Cargo.lock. OPAQUE's library has prior audit history, not an audit of SSync or every current change: https://github.com/facebook/opaque-ke . Construction follows OPAQUE's documented API and Noise PSK processing: https://noiseprotocol.org/noise.html . PAKE-derived key -> Noise NNpsk0 is also used by Magic Wormhole dilation: https://github.com/magic-wormhole/magic-wormhole/tree/master/docs . SSync's integration has an [implementation review and adversarial tests](CRYPTO_REVIEW.md); it still needs independent review before claims of independently audited security.

OPAQUE suite: Ristretto255 OPRF, TripleDH/Ristretto255/SHA-512, Argon2id v0x13 with 64 MiB, 3 passes, 1 lane. Parameters are fixed locally, never supplied by peer. Local listener registration uses its already supplied password; setup/credential are memory-only per listener startup. No on-wire registration, users, scripts or management. TCP connector is OPAQUE client/Noise initiator, regardless of data direction.

Wire handshake: both write 8-byte magic `SSYNC4\0\x01`, 1-byte data-sending role. Roles must differ. OPAQUE's authenticated context includes fixed version/suite label and connector transfer role. Client sends KE1, listener returns KE2, client verifies server proof and sends KE3, listener verifies client proof. Length-prefixed handshake messages limited to 2048 bytes. HKDF-SHA256 with context as salt and domain label `SSync-4 Noise PAKE session PSK` derives a 32-byte Noise PSK from the OPAQUE session key. Fresh Noise `NNpsk0_25519_ChaChaPoly_SHA256` handshake with authenticated connector/listener confirmation payloads; context is Noise prologue. Final encrypted ready-connector / ready-listener exchange gates transfer engine. Missing/incomplete confirmation gives no metadata/root access.

Ordinary transfer handshakes have a 15-second deadline; socket read/write timeouts are updated between steps. Connections have independent ephemeral keys; passwords never expire. After authentication, 120-second idle I/O timeout, no whole-transfer deadline. Noise uses ordered implicit nonces; modified, replayed, reordered or duplicated ciphertext fails authentication. No 0-RTT or early data. Ciphertext record <=60,016 bytes; logical message <=1 MiB, with logical length inside AEAD. Unauthenticated outer sizes are bounded before allocation. Peer/root metadata is encrypted after confirmation; record lengths, timing, addresses and clear send/receive roles leak.

Brute-force controls and transfer state specification are completed alongside implementation. Rate limiting is temporary and in-memory, reset on process restart; it is not a distributed/DoS guarantee. Strong random credentials are recommended. Endpoint compromise can expose reusable passwords and private resume state; local OS access, terminal/history/environment exposure and authorized malicious peers are separate threats. OPAQUE resists capture-based offline guessing, not password theft. No independent cryptographic audit is claimed.

## Transfer state machine and channel binding

The channel binds protocol/suite and data roles. Each endpoint retains its local root capability; the remote never supplies an ambient filesystem root. Reusing a credential across listeners authorizes its holder for every root that operator configured with it; this is password-holder authentication, not certificate/hostname identity. Use distinct secrets for separate trust scopes.

After mutual ready, receiver sends encrypted `Options {merge,dryrun,skip}`. Sender validates its selected local paths and sends `Begin {roots:[(basename,is_dir)],skip,dryrun,nodelete}`. Connector's encrypted approval gates changes. Dryrun and nodelete are reductions: either peer can request them; a peer cannot enable deletion when the receiver forbids it. Receiver enforces path/layout/filter permissions independently.

Traversal sends directory messages and file headers `(relative path,size,BLAKE3,mtime seconds/nanoseconds)`. Headers are bounded and strict; unknown fields/operations fail. Receiver returns `Need {skip:true}` only after whole-file digest/length match. Otherwise fixed 200,000-byte blocks are streamed through a one-block lookahead window:

1. Sender advertises current block offset/length/BLAKE3.
2. Receiver compares private resume ranges and existing target, replying `Want {yes,reused}`.
3. Sender advertises the next block (or strict `WindowEnd {}`), then sends the current raw payload if requested.
4. A bounded receiver worker compares the next range with positional reads while current data arrives/is staged; bounded source hash/read queue runs concurrently. Queues have capacity two. Metadata/data order is enforced, and only one future block is advertised.
5. Received block digest is checked before write/ack. Matching ranges are copied locally. Preview misses are not reported as reused bytes.
6. Sender rehashes/checks source state before final `EndFile`; receiver verifies complete reconstructed bytes, exact length and supported mtime, fsyncs and atomically replaces one file. Existing targets must retain their prior identity through commit checks.

`Done` must match the full duplicate-free verified entry count. Only then may receiver remove extras inside selected directory scopes, protecting skip paths and honoring nodelete/dryrun. Final acknowledgement reports content/reuse/deletion counters. No tree-wide transaction: successful earlier files/directories remain when a later file fails. `verify` adds local tree digests; per-file content verification is always mandatory. `wire_sent`/`wire_received` counters measure encrypted ready/application records including framing; they exclude OPAQUE/Noise setup and TCP/IP overhead.

## Bounds and lifecycle

- 15-second authentication deadline including admission-work waiting, plus OS connection deadlines; 120-second post-auth socket idle timeout, no total transfer-duration cutoff.
- At most four expensive OPAQUE registration/handshake operations per process; eight sessions/four authenticating workers per listener; 128 tracked sockets per process. No unbounded acceptance queue in application code.
- Admission: per IP five-token burst, one refill per five seconds; listener-wide twenty-token burst, one refill per second. Rejected per-IP attempts do not spend global credits, and globally rejected new IPs do not allocate tracking state. Correct mutual authentication returns its admission credit, so legitimate repeated use does not consume the failed-guess budget. After five IP failures, temporary exponential delay 5–60 seconds; twenty global failures cause a 30-second delay. Valid auth never erases global failure history. Expiring IP state is capped at1024 entries/300 seconds. Rates are in-memory and reset on restart; flooding can affect availability, not permanently expire credentials or revoke established sessions.
- 1 MiB logical messages, 60,016-byte cipher records, 2048-byte handshake frames; 4096-byte passwords; 16GiB files; 10,000 manifest entries/8MiB path strings; 64 path components/4096 bytes/255-byte names; 128 selected roots; 32 filters per peer, 1024 bytes per filter; 32 config commands/1MiB config.
- Private receiver state: at most128 files/16GiB prospective total logical size per root. The `.ssync-state` name is reserved: scanners exclude recognizable private state (0700 directory, up to 128 same-owner single-link 0600 files with 64-hex names) and reject other collisions instead of silently omitting user data. Retained partial IDs are keyed by the reusable credential and path/size/content identity under a pinned root. Ranges are rehashed on reuse. No automatic credential expiry; abandoned state may need local operator cleanup. Private state/credentials on disk are endpoint-compromise material, not PAKE network transcripts.
- Receiver holds an advisory root-descriptor lock. Graceful SIGINT/SIGTERM closes tracked sockets and stops workers; kernel close releases locks after abrupt process death. Persistent connectors retry with two-second delay; persistent listeners log failed sessions and remain available.

## Filesystem and metadata policy

Linux64/openat2/procfs required. All operations are directory-relative with `RESOLVE_BENEATH|NO_SYMLINKS|NO_MAGICLINKS|NO_XDEV`; locally chosen directory roots may be mounts/subvolumes, traversals may not cross child mounts or change device ID (including Btrfs subvolumes). Existing/created directories must not be group/other writable. Version 4.1.1 additionally checks current-user/root ownership for writable roots and write-path directories, validates trusted ancestry (allowing trusted sticky ancestors), and applies these ancestry checks to configs/password files. Read-only sources may have other owners. Successful directory creation/deletion fsyncs its parent; fsync failure is a reported operation failure. Regular files must have one link; no symlink/hardlink creation, devices, FIFOs or sockets. Only content/structure and supported file mtimes transfer; remote modes, ownership, ACLs and executable bits do not. Receiver files are0600/new directories0700. Type conflicts fail instead of deleting old targets recursively.

Filesystem types are restricted to local ext-family, Btrfs, XFS, tmpfs, ramfs and overlay; casefold directories are rejected through Linux FS_IOC_GETFLAGS. Case-insensitive/network/FUSE/pseudo filesystems and non-Linux platforms are unsupported. Actual validation covers Btrfs developer tests and tmpfs peers, not every allowed filesystem combination. Linux casefold behavior: https://www.kernel.org/doc/html/latest/admin-guide/ext4.html . No string-prefix containment fallback. A local process with the same identity or privileged filesystem control can modify the authorized tree/credentials; endpoint compromise is outside the remote-peer boundary. Advisory locks coordinate SSync processes, and detected external edits fail; this is not a general OS transactional isolation mechanism.

## Backup upload extension (4.1)

Backup-only magic is `SSYNCB\0\x01`; connector role is always sending (1), listener always receiving (0). Ordinary 4.0 peers fail before file metadata. OPAQUE context adds `/backup-upload-v1`. Client sends one blinded KE1. Server replies with a length-prefixed single-byte candidate count (1..32), then one bounded KE2 per configured bay, each using independently generated local server setup/record. Client tests candidates with a clone of its own KE1 state using the same fixed Argon2 parameters, consumes all responses, then returns KE3 prefixed with the selected single-byte index. No password hash/routing digest is published. Unknown-password failures are generic. Count, ordering and selected index are public; this is not bay anonymity. Trying candidates costs client CPU linearly in the bay count, with at most one 64 MiB Argon2 operation per connection at a time. A network attempt tests one guessed password against up to 32 bays; admission budgets are listener-wide and per IP. Prefer generated passwords.

Selected index is appended to context before HKDF and Noise prologue, binding selection to the confirmed encrypted channel. Candidate KE2/KE3 use the backup context; swapping/replaying them cannot establish a confirmed session for another password. All ordinary mutual Noise/ready confirmations remain. Backup wall-clock authentication limit is 60 seconds for candidate processing, with at most four sessions per listener and four expensive operations per process. Ordinary transfer authentication stays at 15 seconds. This extension is application code using the [library login API](https://docs.rs/opaque-ke/4.0.1/opaque_ke/); it has no independent cryptographic audit.

After encrypted mutual ready, server attempts a nonblocking bay lock and sends an encrypted boolean availability result. False means busy and the connection closes; true starts the existing upload transfer state machine. Roots are selected only from local configuration; no remote path-selection or download dispatch exists. Config parsing/preflight checks locally authorized directory metadata before listening, but transfer contents and protocol metadata remain gated on authentication. Existing directory-relative no-follow path protection, cross-process root locking, credential-bound private resume, manifest-gated deletion and atomic per-file commits apply. Backup preflight also rejects underlying filesystem path overlap through bind aliases, using descriptor mount IDs and bounded kernel mount metadata without scanning file contents. Mount topology must remain stable under administrator control. Same-credential multi-server use is one trust group; compromised servers know their configured plaintext secret. Stored files are ordinary unencrypted files under OS access control.

## Authenticated comparison disclosure

Skip/reuse responses disclose whether an authenticated sender's guessed file/block content matches stored data, even in a dry run. Backup upload-only dispatch exposes no raw download operation, but it does not provide content-presence secrecy from a password holder. Use distinct credentials across trust scopes and keep unrelated server-only secrets outside writable bays. This is an intentional consequence of the current efficient delta comparison; see [security review](SECURITY_REVIEW.md) for the executed probe and remaining boundaries.

## Integration hardening (4.1.1)

Application-owned OPAQUE result export keys are explicitly wiped; session results enter zeroizing guards before later fallible candidate reads/KE3 writes. Full upstream/stack/register key erasure is not guaranteed. Encrypted framing, authentication, I/O or decoded-message failure permanently closes the channel; reconnect performs a fresh login. Wire formats/suites are unchanged. A rogue backup listener can present up to 32 candidate password guesses per connecting client invocation, so the wrapper has bounded interactive guessing amplification in both directions. See [CRYPTO_REVIEW.md](CRYPTO_REVIEW.md) for the construction analysis, tests and residual limits.
