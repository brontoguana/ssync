# SSync 4 authenticated channel

Selected libraries: opaque-ke 4.0.1 and snow 0.10, locked in Cargo.lock. OPAQUE's library has prior audit history, not an audit of SSync or every current change: https://github.com/facebook/opaque-ke . Construction follows OPAQUE's documented API and Noise PSK processing: https://noiseprotocol.org/noise.html . PAKE-derived key -> Noise NNpsk0 is also used by Magic Wormhole dilation: https://github.com/magic-wormhole/magic-wormhole/tree/master/docs . SSync's integration has an [implementation review and adversarial tests](CRYPTO_REVIEW.md); it still needs independent review before claims of independently audited security.

OPAQUE suite: Ristretto255 OPRF, TripleDH/Ristretto255/SHA-512, Argon2id v0x13 with 64 MiB, 3 passes, 1 lane. Parameters are fixed locally, never supplied by peer. Local listener registration uses its already supplied password; setup/credential are memory-only per listener startup. No on-wire registration, users, scripts or management. TCP connector is OPAQUE client/Noise initiator, regardless of data direction.

Wire handshake: both write 8-byte magic `SSYNC4\0\x01`, 1-byte data-sending role. Roles must differ. OPAQUE's authenticated context includes fixed version/suite label and connector transfer role. Client sends KE1, listener returns KE2, client verifies server proof and sends KE3, listener verifies client proof. Length-prefixed handshake messages limited to 2048 bytes. HKDF-SHA256 with context as salt and domain label `SSync-4 Noise PAKE session PSK` derives a 32-byte Noise PSK from the OPAQUE session key. Fresh Noise `NNpsk0_25519_ChaChaPoly_SHA256` handshake with authenticated connector/listener confirmation payloads; context is Noise prologue. Final encrypted ready-connector / ready-listener exchange gates transfer engine. Missing/incomplete confirmation gives no metadata/root access.

Ordinary transfer handshakes have a 15-second deadline; socket read/write timeouts are updated between steps. Connections have independent ephemeral keys; passwords never expire. After authentication, 120-second idle I/O timeout, no whole-transfer deadline. Noise uses ordered implicit nonces; modified, replayed, reordered or duplicated ciphertext fails authentication. No 0-RTT or early data. Ciphertext record <=60,016 bytes; logical message <=1 MiB, with logical length inside AEAD. Unauthenticated outer sizes are bounded before allocation. Peer/root metadata is encrypted after confirmation; record lengths, timing, addresses and clear send/receive roles leak.

Brute-force controls and transfer state specification are completed alongside implementation. Rate limiting is temporary and in-memory, reset on process restart; it is not a distributed/DoS guarantee. Strong random credentials are recommended. Endpoint compromise can expose reusable passwords and private resume state; local OS access, terminal/history/environment exposure and authorized malicious peers are separate threats. OPAQUE resists capture-based offline guessing, not password theft. No independent cryptographic audit is claimed.

## Transfer state machine and channel binding

The channel binds protocol/suite and data roles. Each endpoint retains its local root capability; the remote never supplies an ambient filesystem root. Reusing a credential across listeners authorizes its holder for every root that operator configured with it; this is password-holder authentication, not certificate/hostname identity. Use distinct secrets for separate trust scopes.

After mutual ready, receiver sends encrypted `Options {merge,dryrun,skip,permissions:true,chmod:optional_octal_mode}` (4.1.4 permission extension). Sender validates its selected local paths and sends `Begin {roots:[(basename,is_dir)],skip,dryrun,nodelete}`. Before Begin, source configuration suffixes are projected to `.ssyncbak` and link descriptions are planned with collision/size checks. Configured password-file paths and inode aliases are excluded locally. An empty root list represents an excluded/no-op selection: it permits no entries or mirror deletion, even with merge. Connector's encrypted approval gates changes. Dryrun and nodelete are reductions: either peer can request them; a peer cannot enable deletion when the receiver forbids it. Receiver enforces path/layout/filter permissions independently.

Traversal sends directory messages `(relative path,mode)` and file headers `(relative path,size,BLAKE3,mtime seconds/nanoseconds,mode)`. Modes contain only `0o777` rwx bits. Optional file overrides apply with receiver priority; directories always retain source modes. Descriptions default to0600 unless overridden. The receiver validates incoming modes before applying its local override. Unreadable existing regular files cannot provide comparison blocks but can be atomically replaced via their writable parent without changing the old file first. A merge directory message uses the empty relative path solely for the single selected source directory and counts as an entry. Updated senders refuse receivers without `permissions:true` before Begin; old senders reject the new Options before any transfer mutation. Ordinary and backup transfers both require 4.1.4 or later for permission preservation. Headers are bounded and strict; unknown fields/operations fail. Receiver returns `Need {skip:true}` only after whole-file digest/length match. Otherwise fixed 200,000-byte blocks are streamed through a one-block lookahead window:

1. Sender advertises current block offset/length/BLAKE3.
2. Receiver compares private resume ranges and existing target, replying `Want {yes,reused}`.
3. Sender advertises the next block (or strict `WindowEnd {}`), then sends the current raw payload if requested.
4. A bounded receiver worker compares the next range with positional reads while current data arrives/is staged; bounded source hash/read queue runs concurrently. Queues have capacity two. Metadata/data order is enforced, and only one future block is advertised.
5. Received block digest is checked before write/ack. Matching ranges are copied locally. Preview misses are not reported as reused bytes.
6. Sender rehashes/checks source state before final `EndFile`; receiver verifies complete reconstructed bytes, exact length and supported mtime, fsyncs and atomically replaces one file, then applies and synchronizes its source mode before acknowledgment. Resume staging remains private. Content-identical files also receive source permissions before Need/skip. Existing targets must retain their prior identity through commit checks.

`Done` must match the full duplicate-free verified entry count. Only then may receiver remove extras inside selected directory scopes, protecting skip paths and honoring nodelete/dryrun. Final acknowledgement reports content/reuse/deletion counters. No tree-wide transaction: successful earlier files/directories remain when a later file fails. `verify` adds local tree digests; per-file content verification is always mandatory. `wire_sent`/`wire_received` counters measure encrypted ready/application records including framing; they exclude OPAQUE/Noise setup and TCP/IP overhead.

Updated peers advertise correlated diagnostics by splitting each authenticated ready message into two Noise records, with a five-byte first plaintext record containing the existing four-byte length and one payload byte. The connector advertises first and the listener only mirrors the split when it sees that advertisement. Older peers reassemble the unchanged ready payload and continue their existing application protocol. The ID is a domain-separated BLAKE3 derivation from the fresh completed Noise handshake hash, rendered as nine characters from a 32-character alphabet in three groups. It is a log correlation label only.

After mutual advertisement, either peer can send a terminal encrypted `Failed {report:{reason,phase,operation,entry}}` message. It carries a fixed reason code, an optional receiver phase and operation, and an optional relative transfer entry. The other peer determines the failure side from the channel role. The same summary appears on both ends when delivered. Absolute paths, receiver-only mirror entries, private staging paths, credentials and raw error text stay in local logs. If an endpoint or the network vanishes, the surviving peer prints the ID and where it detected the interruption, and leaves the origin unresolved. Failed authentication has no shared transfer ID. When both support diagnostics, the sender responds to `Finished` with `Confirmed` after checking the final counts and doing any requested local verification. A mixed session with a released 4.1.4 or 4.1.5 peer retains the prior application messages. Only the updated peer logs the ID. In 4.1.7, both the transfer and diagnostics wire formats are unchanged.

## Bounds and lifecycle

- 15-second authentication deadline including admission-work waiting, plus OS connection deadlines; 120-second post-auth socket idle timeout, no total transfer-duration cutoff.
- At most four concurrent OPAQUE registration or computation operations per process. Waiting for peer I/O does not hold an OPAQUE work permit. At most eight authenticated transfers per ordinary continuous listener or four per backup listener. Each persistent listener allows up to eight pending handshakes, with four per source IP (IPv4-mapped addresses count as IPv4). One-shot listeners authenticate serially. Up to 64 pending inbound handshakes and 128 tracked sockets per process. No unbounded application acceptance queue.
- Admission: per IP five-token burst, one refill per five seconds; listener-wide twenty-token burst, one refill per second. Per-IP refusals do not spend global credits. Correct mutual authentication returns its admission credit. After five failures from one IP, that IP is delayed for 5–60 seconds. Expiring IP state is capped at 1024 entries and retained for up to five minutes after its last rate update, or while a handshake is pending. A distributed flood can still exhaust the listener-wide rate or pending capacity. Established sessions retain their slots.
- 1 MiB logical messages, 60,016-byte cipher records, 2048-byte handshake frames; 4096-byte passwords; 16GiB files; 64 path components/4096 bytes/255-byte names; 128 selected roots; 32 filters per peer, 1024 bytes per filter; 32 config commands/1MiB config.
- Default local bounds are 10,000 entries per directory listing or manifest, and
  8 MiB of cumulative manifest path bytes. The `large-transfer` qualifier lifts these
  bounds locally. A peer cannot enable it remotely.
- Private receiver state: at most128 files/16GiB prospective total logical size per root. The `.ssync-state` name is reserved: scans and mirror cleanup always exclude it without inspecting ownership/type/contents. Explicit source selections are omitted, including paths relative to a reserved-state working directory; unrelated data must use a different name. Receiving state still requires a current-user-owned 0700 directory with bounded single-link private 0600 files. A stage path/inode colliding with the configured password file is rejected before writing. Retained partial IDs are keyed by the reusable credential and path/size/content identity under a pinned root. Ranges are rehashed on reuse. No automatic credential expiry; abandoned state may need local operator cleanup. Private state/credentials on disk are endpoint-compromise material, not PAKE network transcripts.
- Receiver holds a Linux advisory `flock` on the open destination directory. Another cooperating process cannot acquire an exclusive lock on that same directory inode until all copies of the first locking descriptor close. Normal completion, worker cleanup and process death release it. The lock protects the exact receiving root and does not reserve ancestors and descendants as a group. On contention, the receiver looks for a holder in `/proc/locks` and reports the observed PID and available process name locally. If the reported device differs from the directory device, the receiver verifies the candidate through its open descriptors. Locks that have cleared or are hidden by process visibility restrictions can leave the holder unknown. Private `.ssync-state` partials can remain after interruption for verified resume. Persistent connectors retry with two-second delay; persistent listeners log failed sessions and remain available.

## Filesystem and metadata policy

Linux64/openat2/procfs required. All operations are directory-relative with `RESOLVE_BENEATH|NO_SYMLINKS|NO_MAGICLINKS|NO_XDEV`; locally chosen directory roots may be mounts/subvolumes, traversals may not cross child mounts or change device ID (including Btrfs subvolumes). Directory transfers allow shared-writable paths by default since 4.1.2; local `sole-owned` retains the earlier rejection of group/other-writable directories. Under that strict policy receivers also check current-user/root ownership for writable roots and write-path directories and trusted ancestry (allowing trusted sticky ancestors). Configuration/password paths retain their separate protections. Read-only sources may have other owners. Successful directory creation/deletion fsyncs its parent; fsync failure is a reported operation failure. Destination and configuration regular files must have one link; no symlink/hardlink creation, devices, FIFOs or sockets. Source-only inspection pins the final entry with O_PATH/O_NOFOLLOW. readlinkat on the pinned symlink reads target bytes without traversing them. Source hard-linked regular files may be read but are copied into independent single-link files. A bounded projected-name preflight emits inert .ssynclink descriptions using ordinary File/block/hash messages, includes their projected roots in the authorized layout, and rejects source/description collisions. Link identity is checked before and after transfer. UTF-8 targets are JSON-quoted, otherwise byte-preserving path_hex is used; description targets are never interpreted by the receiver. Published versions through 4.1.3 transfer content/structure and supported file mtimes, creating files0600/directories0700. The 4.1.4 permission extension additionally copies source rwx bits, including executable bits; ownership, groups, ACLs and special mode bits are excluded. New directories remain temporarily0700 and existing directories temporarily retain owner access until cleanup/verification finishes. Recorded directory identities are checked before finalizing source modes from deepest to shallowest, including on normal transfer errors. Forced termination can leave temporary modes; a rerun reapplies source metadata. Local sole-owned policy rejects group/other-writable source directory modes. Metadata update errors fail the transfer. Type conflicts fail instead of deleting old targets recursively.

Before preparing incoming directories or staging changed/new files, the receiver checks its own filesystem's reported capacity. It repeats the check before each block write, allowing for that block, and before publishing a file. The receiver stops if usage would exceed 99% of blocks available to unprivileged writers. The same checks apply to backups. Completed files and private partials remain as with other transfer failures. Dry runs and content-identical regular files need no data allocation. This is a filesystem-wide check with no per-bay quota or reservation across concurrent sessions. Filesystems without a fixed reported capacity, such as ramfs, have no percentage cutoff.

Filesystem types are restricted to local ext-family, Btrfs, XFS, tmpfs, ramfs and overlay; casefold directories are rejected through Linux FS_IOC_GETFLAGS. Case-insensitive/network/FUSE/pseudo filesystems and non-Linux platforms are unsupported. Actual validation covers Btrfs developer tests and tmpfs peers, not every allowed filesystem combination. Linux casefold behavior: https://www.kernel.org/doc/html/latest/admin-guide/ext4.html . No string-prefix containment fallback. A local process with the same identity or privileged filesystem control can modify the authorized tree/credentials; endpoint compromise is outside the remote-peer boundary. Advisory locks coordinate SSync processes, and detected external edits fail; this is not a general OS transactional isolation mechanism.

## Backup upload extension (4.1)

Backup-only magic is `SSYNCB\0\x01`; connector role is always sending (1), listener always receiving (0). Ordinary 4.0 peers fail before file metadata. OPAQUE context adds `/backup-upload-v1`. Client sends one blinded KE1. Server replies with a length-prefixed single-byte candidate count (1..32), then one bounded KE2 per configured bay, each using independently generated local server setup/record. Client tests candidates with a clone of its own KE1 state using the same fixed Argon2 parameters, consumes all responses, then returns KE3 prefixed with the selected single-byte index. No password hash/routing digest is published. Unknown-password failures are generic. Count, ordering and selected index are public; this is not bay anonymity. Trying candidates costs client CPU linearly in the bay count, with at most one 64 MiB Argon2 operation per connection at a time. A network attempt tests one guessed password against up to 32 bays; admission budgets are listener-wide and per IP. Prefer generated passwords.

Selected index is appended to context before HKDF and Noise prologue, binding selection to the confirmed encrypted channel. Candidate KE2/KE3 use the backup context; swapping/replaying them cannot establish a confirmed session for another password. All ordinary mutual Noise/ready confirmations remain. Backup wall-clock authentication limit is 60 seconds for candidate processing, with up to four authenticated uploads per listener and the pending-handshake limits above. Ordinary transfer authentication stays at 15 seconds. This extension is application code using the [library login API](https://docs.rs/opaque-ke/4.0.1/opaque_ke/); it has no independent cryptographic audit.

After encrypted mutual ready, server attempts to reserve the bay’s single session slot and an authenticated transfer slot before sending an encrypted boolean availability result. False means busy and the connection closes; true starts the existing upload transfer state machine. Roots are selected only from local configuration; no remote path-selection or download dispatch exists. Config parsing/preflight checks locally authorized directory metadata before listening, but transfer contents and protocol metadata remain gated on authentication. Existing directory-relative no-follow path protection, cross-process root locking, credential-bound private resume, manifest-gated deletion and atomic per-file commits apply. Backup preflight also rejects underlying filesystem path overlap through bind aliases, using descriptor mount IDs and bounded kernel mount metadata without scanning file contents. Mount topology must remain stable under administrator control. Same-credential multi-server use is one trust group; compromised servers know their configured plaintext secret. Stored files are ordinary unencrypted files under OS access control.

## Authenticated comparison disclosure

Skip/reuse responses disclose whether an authenticated sender's guessed file/block content matches stored data, even in a dry run. Backup upload-only dispatch exposes no raw download operation, but it does not provide content-presence secrecy from a password holder. Use distinct credentials across trust scopes and keep unrelated server-only secrets outside writable bays. This is an intentional consequence of the current efficient delta comparison; see [security review](SECURITY_REVIEW.md) for the executed probe and remaining boundaries.

## Integration hardening (4.1.1)

Application-owned OPAQUE result export keys are explicitly wiped; session results enter zeroizing guards before later fallible candidate reads/KE3 writes. Full upstream/stack/register key erasure is not guaranteed. Encrypted framing, authentication, I/O or decoded-message failure permanently closes the channel; reconnect performs a fresh login. Wire formats/suites are unchanged. A rogue backup listener can present up to 32 candidate password guesses per connecting client invocation, so the wrapper has bounded interactive guessing amplification in both directions. See [CRYPTO_REVIEW.md](CRYPTO_REVIEW.md) for the construction analysis, tests and residual limits.
