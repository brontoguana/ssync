# SSync 4 command contract

The Java reference is 3.3. Version 4.0 changes the wire protocol, retaining CLI usage. Regular files and directories are copied; the 4.1.4 link extension represents source symlinks as inert `.ssynclink` descriptions and copies hard-linked contents independently with relationship descriptions. No process execution, scripts, remote management, ownership or ACL changes. The 4.1.4 permission extension copies source read/write/execute bits, including executable bits, and requires updated peers at both ends. Special mode bits are excluded.

`ssync [qualifiers] put|get|offer|accept location [paths...]`

`put`/`offer` send; `get`/`accept` receive. A location without a host listens; `host:port`, `host:alias`, `[IPv6]:port` connects, independently of data direction. `put`/`get` perform one successful session; `offer`/`accept` listeners persist with reusable credentials. Continuous connectors repeat after successful sessions, retry bounded-delay connection failures, and stop on operator cancellation. No credential expires.

Aliases use Java UTF-16 String.hashCode: 1000 + ((hash & 0x7fffffff) % 50000), including literal `alias/`. Numeric ports must be 1..65535 (invalid numeric ports fail rather than becoming aliases).

Password precedence: nonempty SSYNC_PASSWORD, then SSYNC_PASSWORD_FILE, then SSYNC_PASSWORD_FD, otherwise password@location, otherwise hidden connector prompt or generated listener password. Inline passwords are always stripped from location, even when environment overrides them (fixes legacy parsing bug). Passwords are preserved exactly, 16+ Unicode characters and at most 4096 UTF-8 bytes. Generated secrets: 24 uniformly sampled Base58 characters in six groups of four. `ssync pwd` emits only password + newline. No additional composition/blocklist policy. Passwords are zeroized on drop where library types support it; environment/arguments are exposed to the local OS/operator.

Paths default to `.`. Senders allow multiple selected files/directories. Receivers authorize exactly one existing directory. Without `merge`, each selected sender item appears under its basename. Receiver `merge` merges one directory's contents into the receiver root. Duplicate basenames fail. Missing receiver roots must be created locally by the operator; no preauthentication root creation.

Qualifiers precede action: `merge`, `nodelete`, `dryrun`, `verify`, `verbose`, `force`/`noprompt`, `sole-owned`, `skip:substring`, `--chmod MODE` / `chmod:MODE` (`permissions` aliases). Matching is case-insensitive for command words; filter values/passwords remain case-sensitive. `skip:` protects matching paths from transfer AND deletion on either side. Defaults retain overwrite and scoped mirroring deletion: delete extraneous entries only inside transferred directories after all files/complete manifest verify. Single-file upload never deletes neighbours. `nodelete` disables deletion. `dryrun` negotiates a write-free preview on both peers. `force`/`noprompt` skips interactive transfer confirmation only. Roots and local directory policies cannot be expanded by wire options. The 4.1.4 permission extension reproduces source rwx modes for regular files and directories (including content-identical files); merge and backup layouts also copy the source-root mode to the destination root. An optional octal file-mode override (000..777, optional leading zero) affects all copied regular files, including content-identical files and link descriptions. Either side may specify it; the receiving override wins. Directories retain source modes. Symbolic modes and special bits are rejected. Ownership, groups, ACLs and special mode bits are not copied. `sole-owned` receivers reject source directory modes with group/other write bits. Private partials remain `0600` under `0700` state directories. Directories retain owner access during traversal and mirror cleanup; their source modes are finalized from children to parents on success and normal errors. Forced termination can leave temporary directory modes or a just-renamed file at `0600`; rerun the transfer to complete metadata. A metadata failure fails the transfer. Dry runs change no modes. Changed/new files retain their source modification time, as in Java; completely matching files retain their existing timestamps. File/directory type conflicts fail rather than recursively removing the old target. `verify` prints a modern verified tree digest; content validation always occurs regardless of qualifier.

Source link extension (unreleased): `X` symlinks become `X.ssynclink` with `type: softlink`, JSON-quoted `path` and manual recreation instructions. Non-UTF-8 targets use `path_hex`. No target is followed. Hard-linked regular files retain contents as independent files and get `type: hardlink` descriptions; partner paths are relative to the receiving transfer root, or `path: null` if other names are not selected. Descriptions default to mode0600 unless overridden. A bounded preflight rejects projected-name collisions before Begin. Source/link identity changes fail, filters protect originals and projected paths, `.ssync` remains protected, and dry runs write nothing. Descriptions use ordinary verified file messages and participate in scoped mirror cleanup. Destination links and special files remain rejected; no actual links are created. See README for examples.

Local diagnostics: `version`/`--version`, `hash directory`, `deep file` (200,000-byte BLAKE3 hashes), `scan file` (byte count), file-only argument (inspection), `?` interactive guidance, no args/`--help` usage. The unreleased help adds `--help <topic>` / `help <topic>` for permissions, links, mirroring, passwords, config, backup and compatibility. Hashes intentionally differ from legacy Java MD5/long formatting. Terminal controls in filenames are escaped.

A single `.ssync` argument loads UTF-8 declarative transfer commands, quoted using shell-like tokenization without shell expansion/execution. Blank lines/comments ignored. At most 32 commands/1 MiB config; only transfer commands allowed, fully validated before workers start. Concurrent workers share cancellation; failures produce nonzero status. Config must be regular, single-link and not group/other writable. Shared-writable parent directories warn once on stderr and do not prevent execution. `ssync sole-owned file.ssync` retains strict configuration-directory checks and enables the local strict directory policy for all contained transfers. Password-file and backup-configuration path protections are unchanged. Relative paths use process CWD, retaining legacy semantics.

`install`, `update`, `uninstall` are local standalone commands, never wire/config operations. Installation is `/usr/local/bin/ssync` with private SSync ownership record; directory override SSYNC_INSTALL_DIR supports disposable testing. Root required in default location. Native APIs only. Update reads github.com/brontoguana/ssync releases, reports current/latest/release details, selects platform, verifies SHA-256 before atomic install; checksum authenticity depends on GitHub release/account security. No remote scripts. Uninstall verifies ownership/hash and removes only owned files; unrelated or locally modified installations fail safely.

Initial verified release platform: Linux x86_64, standalone musl binary. Linux aarch64 builds/testing and macOS support require their own validation. Windows unsupported. Path safety requires Linux openat2 (kernel 5.6+); unsupported kernels fail closed. No unverified platform claims.

Errors and cancellation exit nonzero; persistent listeners log individual session failures and continue. No legacy swallowed worker errors. Per-file atomicity only, no tree transaction. Fixed-block efficiency preserved; inserting bytes can retransmit many blocks. Resume rehashes staged content; private state is credential/root/file bound and bounded. Details and exact resource limits in PROTOCOL.md.

## Backup commands (4.1)

`ssync [verbose sole-owned chmod:MODE] backup-server [port] [file]` defaults to TCP 8425 and `/opt/backup-server.ssync`. A file alone is permitted. Numeric ports or existing aliases are accepted; use an absolute or slash-containing path to disambiguate a single filename that resembles a port. The persistent listener serves at most 32 nonoverlapping bays, one `password=absolute-directory` per line. Password selects the bay; clients cannot choose a remote path.

`ssync [nodelete dryrun verify verbose sole-owned skip:substring chmod:MODE] backup-client [file]` defaults to `/opt/backup-client.ssync`. Every `@hostname[:port]` applies to every `password=absolute-source-directory` entry regardless of ordering. IPv6 uses `@[address][:port]`; ports default to 8425. Existing port aliases work. At most 32 servers and 32 sources. Each source must have a unique password. Environment password inputs do not override explicit configuration secrets. Directory contents merge directly into the selected bay. One invocation performs one cycle without interactive transfer prompts; repeat with a scheduler if desired. Up to four destination workers operate independently; one failure does not cancel others. Exit nonzero if any pair fails.

Both formats ignore blank lines and lines beginning with `#`; entries split on the first `=` and trim surrounding whitespace. Paths may contain spaces, `=`, `#`, and `@`; relative paths are rejected. Missing config files are created exclusively at mode 0600 with commented examples and a generated password, then exit nonzero with setup instructions. Config files must be private (no group/other permissions), owned by the current user or root, regular, single-link, no symlinks, UTF-8, and at most 1 MiB. Validate all syntax and local source/bay directory safety before networking; config paths must stay outside all configured roots. No hot reload; restart after editing. No automatic directory creation. No credentials or config line contents in diagnostics.

Backup channels are distinct from ordinary transfers and accept uploads only. Existing OPAQUE/Noise confirmation remains mandatory before the transfer accesses content. Bay selection uses bounded candidate OPAQUE responses rather than a public password digest. Same-bay concurrent updates fail clearly as busy; different bays can operate concurrently. Latest-copy mirror semantics include deletion after complete verified transfer state; `nodelete`, filters and dry runs apply. Existing fixed-block pipeline, verified resume, full content validation and per-file atomic replacement remain. No native history, whole-tree atomicity, at-rest encryption, network restore, Restic or command execution is added. Each destination scans/hashes independently in this release; persistent scan indexing and shared-source fanout are deferred.

## Unreleased security review hardening

Server bay preflight additionally rejects overlap through bind-mount aliases using kernel-resolved underlying filesystem paths, and enforces config-outside-root checks across aliases. Explicit directory source mounts/subvolumes are permitted as local roots; recursive traversal cannot cross child mounts/device IDs. With `sole-owned`, writable roots and write-path directories must be owned by the current user or root; group/other writable ancestors require sticky protection, and destination directories cannot be group/other writable. These ancestry/permission rules always apply to configuration paths. Read-only sources may belong to other users. Directory creation/deletion synchronizes parent metadata before success. Ordinary config reads enforce their 1 MiB bound even during concurrent growth. Connectors try remaining addresses after a failure, and continuous mode retries resolver errors. Unreleased scanner update: `.ssync-state` is always excluded from source scans and mirror cleanup without inspecting its ownership, type or contents. Explicit source selections of this reserved name are successful no-ops. Receiving staging still validates its own private state and rejects malformed or unsafe state. No command/password/wire format changes. See [findings and remaining security boundaries](SECURITY_REVIEW.md), including the authenticated delta-comparison content oracle.

## Unreleased directory policy

Ordinary and backup transfers accept shared-writable local source/destination directories by default. `sole-owned` precedes any transfer or backup action and applies only on that peer; it is not negotiated over the wire. It rejects group/other write bits on the selected local roots and traversed directories (or the parent of a selected source file). Source ownership remains unrestricted. Receivers additionally retain current-user/root owner and trusted-ancestor checks, including the existing sticky ancestor exception. This is a permission/trust policy, not an exclusive ownership or snapshot guarantee. Installation, password-file and backup-configuration paths retain separate protections; ordinary saved configurations warn for shared parents unless `sole-owned` is requested. `.ssync-state` stays private. Shared destinations trust concurrent local writers and cannot promise isolation from their renames or changes. Descriptor-based link/path/mount containment and file identity checks remain enabled. Configuration protections do not depend on the transfer policy; no wire format change.

Configuration projection (4.1.4, superseding the 4.1.3 skip): ordinary and backup transfers copy source path components ending in `.ssync` (case-insensitive) with `bak` appended. The copy retains contents and the ordinary file-mode rules but is not an executable configuration name. Direct selections project the authorized root too. Bounded link/config name planning rejects collisions before transfer mutation. Filters match original and projected paths. Existing destination `.ssync` paths and descendants remain protected against creation, replacement and mirror deletion, including raw config messages from peers. Local configuration/template reads keep their ownership/mode checks. The explicitly configured `SSYNC_PASSWORD_FILE` (any name) and its hard-link aliases are excluded locally from send/hash, replacement, mode updates and deletion, even when a higher-priority password input is used. Other unidentified secret files require operator exclusions. Empty selections after reserved-state/credential exclusion complete without deletion or permission changes.
