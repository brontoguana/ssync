# SSync 4.0.0 command contract

The Java reference is 3.3. Version 4.0 changes the wire protocol, retaining CLI usage. Only regular-file and directory transfers are supported. No process execution, scripts, remote management, ownership, ACL or executable-mode changes.

`ssync [qualifiers] put|get|offer|accept location [paths...]`

`put`/`offer` send; `get`/`accept` receive. A location without a host listens; `host:port`, `host:alias`, `[IPv6]:port` connects, independently of data direction. `put`/`get` perform one successful session; `offer`/`accept` listeners persist with reusable credentials. Continuous connectors repeat after successful sessions, retry bounded-delay connection failures, and stop on operator cancellation. No credential expires.

Aliases use Java UTF-16 String.hashCode: 1000 + ((hash & 0x7fffffff) % 50000), including literal `alias/`. Numeric ports must be 1..65535 (invalid numeric ports fail rather than becoming aliases).

Password precedence: nonempty SSYNC_PASSWORD, then SSYNC_PASSWORD_FILE, then SSYNC_PASSWORD_FD, otherwise password@location, otherwise hidden connector prompt or generated listener password. Inline passwords are always stripped from location, even when environment overrides them (fixes legacy parsing bug). Passwords are preserved exactly, 16+ Unicode characters and at most 4096 UTF-8 bytes. Generated secrets: 24 uniformly sampled Base58 characters in six groups of four. `ssync pwd` emits only password + newline. No additional composition/blocklist policy. Passwords are zeroized on drop where library types support it; environment/arguments are exposed to the local OS/operator.

Paths default to `.`. Senders allow multiple selected files/directories. Receivers authorize exactly one existing directory. Without `merge`, each selected sender item appears under its basename. Receiver `merge` merges one directory's contents into the receiver root. Duplicate basenames fail. Missing receiver roots must be created locally by the operator; no preauthentication root creation.

Qualifiers precede action: `merge`, `nodelete`, `dryrun`, `verify`, `verbose`, `force`/`noprompt`, `sole-owned`, `skip:substring`. Matching is case-insensitive for command words; filter values/passwords remain case-sensitive. `skip:` protects matching paths from transfer AND deletion on either side. Defaults retain overwrite and scoped mirroring deletion: delete extraneous entries only inside transferred directories after all files/complete manifest verify. Single-file upload never deletes neighbours. `nodelete` disables deletion. `dryrun` negotiates a write-free preview on both peers. `force`/`noprompt` skips interactive transfer confirmation only. Receiver-owned permissions and roots cannot be expanded by wire options. Changed/new files retain their source modification time, as in Java; completely matching files retain their existing timestamps. File/directory type conflicts fail rather than recursively removing the old target. `verify` prints a modern verified tree digest; content validation always occurs regardless of qualifier.

Local diagnostics: `version`/`--version`, `hash directory`, `deep file` (200,000-byte BLAKE3 hashes), `scan file` (byte count), file-only argument (inspection), `?` interactive guidance, no args/`--help` usage. Hashes intentionally differ from legacy Java MD5/long formatting. Terminal controls in filenames are escaped.

A single `.ssync` argument loads UTF-8 declarative transfer commands, quoted using shell-like tokenization without shell expansion/execution. Blank lines/comments ignored. At most 32 commands/1 MiB config; only transfer commands allowed, fully validated before workers start. Concurrent workers share cancellation; failures produce nonzero status. Config must be regular, single-link and not group/other writable. Shared-writable parent directories warn once on stderr and do not prevent execution. `ssync sole-owned file.ssync` retains strict configuration-directory checks and enables the local strict directory policy for all contained transfers. Password-file and backup-configuration path protections are unchanged. Relative paths use process CWD, retaining legacy semantics.

`install`, `update`, `uninstall` are local standalone commands, never wire/config operations. Installation is `/usr/local/bin/ssync` with private SSync ownership record; directory override SSYNC_INSTALL_DIR supports disposable testing. Root required in default location. Native APIs only. Update reads github.com/brontoguana/ssync releases, reports current/latest/release details, selects platform, verifies SHA-256 before atomic install; checksum authenticity depends on GitHub release/account security. No remote scripts. Uninstall verifies ownership/hash and removes only owned files; unrelated or locally modified installations fail safely.

Initial verified release platform: Linux x86_64, standalone musl binary. Linux aarch64 builds/testing and macOS support require their own validation. Windows unsupported. Path safety requires Linux openat2 (kernel 5.6+); unsupported kernels fail closed. No unverified platform claims.

Errors and cancellation exit nonzero; persistent listeners log individual session failures and continue. No legacy swallowed worker errors. Per-file atomicity only, no tree transaction. Fixed-block efficiency preserved; inserting bytes can retransmit many blocks. Resume rehashes staged content; private state is credential/root/file bound and bounded. Details and exact resource limits in PROTOCOL.md.

## Backup commands (4.1)

`ssync [verbose sole-owned] backup-server [port] [file]` defaults to TCP 8425 and `/opt/backup-server.ssync`. A file alone is permitted. Numeric ports or existing aliases are accepted; use an absolute or slash-containing path to disambiguate a single filename that resembles a port. The persistent listener serves at most 32 nonoverlapping bays, one `password=absolute-directory` per line. Password selects the bay; clients cannot choose a remote path.

`ssync [nodelete dryrun verify verbose sole-owned skip:substring] backup-client [file]` defaults to `/opt/backup-client.ssync`. Every `@hostname[:port]` applies to every `password=absolute-source-directory` entry regardless of ordering. IPv6 uses `@[address][:port]`; ports default to 8425. Existing port aliases work. At most 32 servers and 32 sources. Each source must have a unique password. Environment password inputs do not override explicit configuration secrets. Directory contents merge directly into the selected bay. One invocation performs one cycle without interactive transfer prompts; repeat with a scheduler if desired. Up to four destination workers operate independently; one failure does not cancel others. Exit nonzero if any pair fails.

Both formats ignore blank lines and lines beginning with `#`; entries split on the first `=` and trim surrounding whitespace. Paths may contain spaces, `=`, `#`, and `@`; relative paths are rejected. Missing config files are created exclusively at mode 0600 with commented examples and a generated password, then exit nonzero with setup instructions. Config files must be private (no group/other permissions), owned by the current user or root, regular, single-link, no symlinks, UTF-8, and at most 1 MiB. Validate all syntax and local source/bay directory safety before networking; config paths must stay outside all configured roots. No hot reload; restart after editing. No automatic directory creation. No credentials or config line contents in diagnostics.

Backup channels are distinct from ordinary transfers and accept uploads only. Existing OPAQUE/Noise confirmation remains mandatory before the transfer accesses content. Bay selection uses bounded candidate OPAQUE responses rather than a public password digest. Same-bay concurrent updates fail clearly as busy; different bays can operate concurrently. Latest-copy mirror semantics include deletion after complete verified transfer state; `nodelete`, filters and dry runs apply. Existing fixed-block pipeline, verified resume, full content validation and per-file atomic replacement remain. No native history, whole-tree atomicity, at-rest encryption, network restore, Restic or command execution is added. Each destination scans/hashes independently in this release; persistent scan indexing and shared-source fanout are deferred.

## Unreleased security review hardening

Server bay preflight additionally rejects overlap through bind-mount aliases using kernel-resolved underlying filesystem paths, and enforces config-outside-root checks across aliases. Explicit directory source mounts/subvolumes are permitted as local roots; recursive traversal cannot cross child mounts/device IDs. With `sole-owned`, writable roots and write-path directories must be owned by the current user or root; group/other writable ancestors require sticky protection, and destination directories cannot be group/other writable. These ancestry/permission rules always apply to configuration paths. Read-only sources may belong to other users. Directory creation/deletion synchronizes parent metadata before success. Ordinary config reads enforce their 1 MiB bound even during concurrent growth. Connectors try remaining addresses after a failure, and continuous mode retries resolver errors. Reserved `.ssync-state` file/malformed-directory collisions now fail; recognizable private resume state stays excluded. No command/password/wire format changes. See [findings and remaining security boundaries](SECURITY_REVIEW.md), including the authenticated delta-comparison content oracle.

## Unreleased directory policy

Ordinary and backup transfers accept shared-writable local source/destination directories by default. `sole-owned` precedes any transfer or backup action and applies only on that peer; it is not negotiated over the wire. It rejects group/other write bits on the selected local roots and traversed directories (or the parent of a selected source file). Source ownership remains unrestricted. Receivers additionally retain current-user/root owner and trusted-ancestor checks, including the existing sticky ancestor exception. This is a permission/trust policy, not an exclusive ownership or snapshot guarantee. Installation, password-file and backup-configuration paths retain separate protections; ordinary saved configurations warn for shared parents unless `sole-owned` is requested. `.ssync-state` stays private. Shared destinations trust concurrent local writers and cannot promise isolation from their renames or changes. Descriptor-based link/path/mount containment and file identity checks remain enabled. Configuration protections do not depend on the transfer policy; no wire format change.

Configuration protection (4.1.3): ordinary and backup transfers skip paths with a component ending in `.ssync` (case-insensitive), warn, and continue. Neither creation, replacement nor mirror deletion of these paths is allowed; a directory bearing this suffix and its descendants are protected too. Local creation/editing of backup configuration templates remains available.
